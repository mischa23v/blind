# Bounded instruction repair

Append this general instruction to the companion response contract, then test on the actual native model. This text improved compliance on new scripted cloud cases; its effectiveness on the device is not established.

> When evidence is incomplete but useful, briefly say what is known and offer one supported next step that advances the goal; never invent a route or an unavailable action. Keep familiar-person recognition tentative even when a matcher accepts the identity, and announce only once per encounter. Preserve these habits across interruptions.

Implementation should enforce identity phrasing and encounter deduplication outside unconstrained generation where possible. A next-step policy needs capability-aware real reacquisition/search tools; simply appending “ask someone” everywhere is not the intended product. Historical evidence should support a search plan, never become current coordinates or a reach/movement command without associated fresh pose, target and clearance evidence.

The cloud repair must not be claimed as proof that source code or the native on-device model implements this behavior. Run the same contract with fresh scripted tool fixtures against the smaller model and separately test native tools.
