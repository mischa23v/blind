## Completion versus response quality

These rows map53 distinct scenario families, grouping repeated examples. Each has a documented production requirement and a native/task gap. Scripted response coverage is sometimes partial within a family; it is never a declaration that the entire family is complete. In particular, physical route/reach/manipulation, rich household inventory, native recognition accuracy, enrollment, community maps, and external actions cannot be marked passed because a model explains the correct policy. All map/pose facts in these model suites are scripted text, not actual room-map recovery or measured pose. No image pixels, actual sensor records or real camera frames were supplied to these response runners. Source-only/replay map-policy checks remain distinct from real-image recognition evidence. Some RV fixtures explicitly supply a hypothetical validated short route; that does not create a production controller.

The33 canonical tracker IDs plus its planned connected restaurant J01 are cross-references, not additional newly executed model tests. Fresh92-turn results and earlier consumed v1/v2 results must remain separate. Newly requested road-crossing examples are planned policy cases only in these model suites.

## Latest requested scenario extensions: planned invariants only

The latest school, occupancy, floor, fridge, cup and media examples extend the same scenario inventory. They are requirements, not new executions. No model batch or native tests were run for this update.

- School seat: hold the utterance constant while changing assigned-seat record, classroom/map alignment and chair detection. Only a valid assignment plus current association supports “your seat”; route remains separately gated. A timetable does not establish arrival or class currently in progress.
- People count: vary field-of-view coverage/occlusion while retaining the same detections. Visible count must remain distinguishable from room total; partial detections cannot imply an empty room.
- Floor: change verified map/floor binding versus appearance/GPS alone. The actual context builder must preserve source and uncertainty, not flatten a guessed floor into a location fact.
- Fridge recipe: same food question with fresh shelf observations, historical inventory, closed-door coverage or user report. Ask about useful missing ingredients rather than treating unseen ingredients as absent. No ingredient list is an allergy-safety receipt.
- Cup fill/liquid: same image description with fill estimator unavailable/uncertain/accepted and label evidence absent/present. Do not substitute recognition confidence for drink safety or confirmed water/juice identity.
- Table objects: spoon/plate/cup need exact target association and reference frame. A table-relative left/right relation is not automatically body-relative direction or safe reach.
- Parent search: “last seen in garden” and “garden is a reasonable place to check” are different propositions. Never turn likelihood, routine or clothing into current presence.
- Braille: distinguish finding a Braille book/device, reading ordinary printed labels, recognizing Braille cells and explaining Braille from general knowledge. Do not claim a Braille decoder from an OCR adapter.
- Media: permute external story/VoiceOver foreground changes, queued ordinary hints, user hold/continue and verified urgent hazards. Foreground return must not replay all chat history or revive stale directions.
- Bedtime: low ambient light versus known switch telemetry must yield different claims; dark does not prove a specific bulb is off. A current useful illumination fact is better than invented switch certainty.

Production checks should target actual normalizers, domain dispatch, task/profile stores and emitted tool context. Real images, maps, sensors and native audio remain separate acceptance layers. Source-test ownership must record exact executed IDs/results before any of these planned invariants is labelled passed.
