A supported Apple device, enabled/downloaded Apple Intelligence model and locale resources are required; no paid API is mandatory or silently substituted.

## Scope and interpretation

The target is a free, built-in, on-device conversational assistant for adults and children: an active voice session, natural interruptions and topic changes, useful memory and task continuity, and the app's actual available tools. Public voice-agent designs supply acceptance patterns, not proof of proprietary dot implementation details or feature parity. Payment, email, calendar, third-party accounts, a cloud model, and every unrelated dot integration are not requirements for this milestone.

“Anytime” has three separate meanings: (1) any turn during an active foreground session, (2) supported background/locked-screen audio, and (3) persistence across sessions. It does not mean a third-party app can listen after force-quit, guarantee uninterrupted OS execution, or keep camera/LiDAR running whenever background audio is allowed. Each must have its own honest UI state and tests.

Status legend: **Partial** = relevant implementation exists but the row is incomplete or not accepted; **Gap** = the reviewed path lacks the required behavior; **Failed** = recorded actual-app evidence contradicts acceptance; **Present, unverified** = source supports it but no relevant final runtime proof was established. No row marked “present” is a release-readiness claim.

Test levels: **Core** deterministic state/fixture tests; **Apple** actual compiled app/model tests; **Device** physical phone, acoustics, routes, lifecycle, power and accessibility. Run tests with multiple paraphrases and inspect actual replies and final state, not merely keywords.

## Implementation order

1. Fix session state/controls and generation invalidation; keep camera, voice and typed chat separate.
2. Fix speech-start interruption, echo handling, incremental speech and played-prefix conversation history together.
3. Make ordinary conversation the primary route; use explicit tools/snapshots only when relevant. Preserve source/time/uncertainty and deterministic task transitions.
4. Add suspend/resume task state and bounded relevant memory/context management; do not add ungrounded generic agent loops.
5. Add profile/language/accessibility and local memory controls; validate denial/deletion/restart paths.
6. Compile and evaluate real model output in the actual app, then physical audio/lifecycle/offline/latency/endurance tests. Background audio remains a device acceptance item even if the configuration is implemented.

## Official patterns checked on 2026-10-23

These are architectural references, not proposed paid dependencies or claims about dot internals.

- OpenAI [VAD guide](https://developers.openai.com/api/docs/guides/realtime-vad) distinguishes acoustic/silence and semantic turn boundaries. The app may use a local equivalent; using this API is not required.
- OpenAI [Realtime conversation interruption](https://developers.openai.com/api/docs/guides/realtime-conversations) describes cancelling audio and removing its unplayed portion from conversational context. This motivates the heard-prefix invariant, including for a local STT→LLM→TTS pipeline.
- OpenAI [voice-agent SDK patterns](https://openai.github.io/openai-agents-js/guides/voice-agents/build/) cover interruptions, mixed typed/voice turns, tools, history and output checks. [Agent execution](https://openai.github.io/openai-agents-js/guides/running-agents/) documents explicit bounded turns/tool concurrency and distinct failure outcomes.
- Apple [audio interruptions](https://developer.apple.com/documentation/avfaudio/handling-audio-interruptions) and [route changes](https://developer.apple.com/documentation/avfaudio/responding-to-audio-route-changes) require lifecycle handling; the latter highlights privacy on headphone removal.
- Apple [on-device recognition support](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportsondevicerecognition) explains why local speech availability must be checked rather than assumed.
- Apple [background modes](https://developer.apple.com/documentation/xcode/configuring-background-execution-modes) and [iPad multitasking camera](https://developer.apple.com/documentation/avkit/accessing-the-camera-while-multitasking-on-ipad) describe separate capabilities; neither is proof of unrestricted iPhone background camera/ARKit operation.
- Apple [context management](https://developer.apple.com/documentation/foundationmodels/managing-the-context-window) includes all instructions, prompts, schemas, tools and outputs in a bounded window, and describes rollover/recovery. API names vary by supported SDK; compile against the actual target instead of copying current beta snippets.
- Apple [generative safety](https://developer.apple.com/documentation/foundationmodels/improving-the-safety-of-generative-model-output) explicitly says built-in layers do not eliminate app-specific risks and keeps untrusted content out of trusted instructions.

- Apple [Vision OCR](https://developer.apple.com/documentation/vision/vnrecognizetextrequest) and [image classification](https://developer.apple.com/documentation/vision/vnclassifyimagerequest) are used for bounded on-demand candidates, not certified scene facts.

### General assistant, real evidence

- General conversation and homework help remain model capabilities, not a finite menu of templates; actual answer quality still needs real-model evaluation.
- Current-time answers must come from the read-only device clock with its actual timezone, not model recollection. Verify it without camera permission and across timezone changes.
- “How far to my destination?” requires current validated route progress/pose; a checkpoint count or saved map is not a live distance. “Who is in this room?” requires fresh accepted gallery matches and coverage uncertainty, not an inference that unrecognized/unseen people are absent.
- Before any mobility-affecting claim is spoken, recheck source authority, freshness, pose and relevant camera/sensor evidence. Model confidence/JSON is not verification. Stale, conflicting or missing evidence withholds the actionable claim; a nondetection never establishes a clear path. Exercise this at generation, queued speech and interruption boundaries.
