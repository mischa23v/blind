# Navigation reuse decisions — 2026-10-26

## Selected practical path

1. **Use real pinned Recast/Detour**, already selected by the app's `research/ASSISTANT_UPSTREAM_REVIEW.md`, rather than another custom A*. The native adapter in this directory is now built. Recast supplies geometric rasterization/erosion; Detour supplies route search/corridors and low-level obstacle avoidance. Documentation: [modules](https://recastnav.com/), [body radius/height/climb configuration](https://recastnav.com/structrcConfig.html), [query behavior](https://recastnav.com/classdtNavMeshQuery.html).
2. **Keep independent actor truth.** At the selected pin, [`dtCrowd`](https://github.com/recastnavigation/recastnavigation/blob/9f4ce64458dfae86e1239c525ddc219c4e9e06f1/DetourCrowd/Source/DetourCrowd.cpp) owns and constrains position; `addAgent` projects to a nearest navmesh polygon. That behavior can erase a deliberately simulated wrong turn/collision. Use query/corridor and [`dtObstacleAvoidanceQuery`](https://github.com/recastnavigation/recastnavigation/blob/9f4ce64458dfae86e1239c525ddc219c4e9e06f1/DetourCrowd/Include/DetourObstacleAvoidance.h) as candidate producers only.
3. **Then add causal progressive geometry and frontier viewpoints.** The established [Yamauchi frontier method](https://www.robotfrontier.com/papers/cira97.pdf) explores boundaries between observed free and unknown space. The [explore_lite implementation](https://github.com/robo-friends/m-explore-ros2/blob/main/explore/src/frontier_search.cpp) explicitly identifies unknown cells adjacent to free cells. Such cells are exploration boundaries, NOT authorized walking endpoints. Select reachable observed-free standoff viewpoints, keep unknown impassable, and build the same Recast engine only from accepted observed geometry. `explore_lite` ROS2 package declares version1.0.0/BSD-3-Clause and depends on ROS2/Nav2; it was inspected, not installed or adopted. No exact immutable frontier source pin was selected for copying.
4. **Keep goal reaching and avoidance distinct.** Nav2's [maintainer tuning guide](https://docs.nav2.org/rolling/configuration_and_development/tuning_guide/) distinguishes RPP's path tracking from DWB/MPPI's ability to deviate around obstacles. Stop-on-obstacle is not dynamic navigation completion. [Collision Monitor](https://docs.nav2.org/rolling/configuration_and_development/configuration_guide/core_servers/collision_monitor/configuring_collision_monitor_node/) is an independent high-response safety layer, not a global goal solver or hard-real-time safety certification.
5. **Replay already-issued commands when evaluating delay.** Nav2's [merged MPPI delay-replay PR6154](https://github.com/ros-navigation/navigation2/pull/6154) and [migration documentation](https://docs.nav2.org/rolling/configuration_and_development/migration_guides/kilted/Kilted/) model commands still in flight. Do not apply a newly emitted stop/turn instantly in the actor. The original [Dynamic Window paper](https://www.ri.cmu.edu/pub_files/pub1/fox_dieter_1997_1/fox_dieter_1997_1.pdf) restricts candidate velocities using dynamics and stopping admissibility. The local human-response adapter must model delay, turn rate, acceleration, overshoot and bounded errors; no cited robot controller proves human compliance.

## Alternatives and resource boundaries

- Installed and verified: **VTK9.3.1**, **NumPy2.3.5**, **SciPy1.17.0**. VTK root BSD license; NumPy/SciPy BSD-3-Clause with their distributed dependency notices. Existing VTK supplies CPU ray/collision facilities. SciPy [Dijkstra](https://docs.scipy.org/doc/scipy-1.17.0/reference/generated/scipy.sparse.csgraph.dijkstra.html) and [EDT](https://docs.scipy.org/doc/scipy-1.17.0/reference/generated/scipy.ndimage.distance_transform_edt.html) remain diagnostic comparators, **not a parallel navigation authority**. EDT distances are to grid sample centers; a cell-extent and swept-step margin is needed for conservative collision use.
- **Do not install full Nav2 here.** It is absent and adds ROS2/Nav2/TF/pluginlib/runtime dependencies; MPPI additionally lists xtensor/xsimd/OpenMP in the inspected Jazzy manifest. Inspected Jazzy manifests declared1.3.14, RPP Apache-2.0 and MPPI MIT, while current MPPI optimizer source has Apache-2.0 file notices: treat exact-version/file notices separately before any copying. No Nav2 dependency version is selected/adopted here.
- **ORCA/RVO2 is not the default for people.** The [authors' ORCA description](https://gamma.cs.unc.edu/ORCA/) assumes reciprocal sharing of collision avoidance responsibility. RVO2's inspected package metadata declares2.0.3/Apache-2.0. Arbitrary pedestrians or a child ignoring a cue do not satisfy reciprocal ideal-agent assumptions. Not installed/adopted.
- **TileCache is optional later.** [Its updates](https://recastnav.com/classdtTileCache.html) rebuild tiles for unfinished obstacle requests; obstacle insertion is not instant mesh authority. Keep newly observed regions blocked until the requested update is complete. The first small-house adapter does bounded whole-mesh rebuilds instead.
- **Soundscape remains speech/awareness reuse, not a safety proof.** Existing pinned community source `3f24e666ea6dc681cd80498372d9ad84e0f60a44` is MIT; the repo review flags its iOS Thread Sanitizer exclusion/audio race. Its [README](https://github.com/soundscape-community/soundscape/blob/3f24e666ea6dc681cd80498372d9ad84e0f60a44/README.md) describes ambient awareness rather than a collision-free indoor route controller. Tested components do not validate this integration.

## Acceptance plan

First retain the real mesh's invalid-start result. Separately author a valid flat two-room house, explicitly validate spawn and full body dimensions, and run a **known-provided-map** A→B native-engine baseline. Do not relocate a failing real start or call supplied geometry unknown-map success.

Then run the identical engine behind a separate observer process: measured synthetic chest-camera FOV/occlusion/range/timestamp, only accepted causal points/cells, no hidden mesh or future observations. A finite supported map without a route triggers safe viewpoint exploration/replanning, not invented free space. A dynamic blocker must lead to an actual alternate-route completion where an alternate exists; waiting/stopping alone is a failure of that goal-reaching test.

Predeclare held-out layout families (not just seed changes): two-room door, L corridor, cluttered multi-room house, cul-de-sac/backtrack, alternative door with moved blocker, narrow passage, overhang, drop/unsupported floor, loop/return. Include normal bounded noise and combinations of sensor delay, command delay/jitter, yaw/pitch/mount drift, overshoot, wrong turns, tracking interruption and independently moving obstacles.

**Episode success = reached specified B within goal tolerance, near-zero terminal speed, zero body/head collision or support loss, within the preregistered time budget.** Report invalid setup, unreachable, collision, deadlock, timeout and tracking-lost separately. For reachable in-domain layouts, stop-only/deadlocked cases are not successes. Report per-layout completion/health loss, time/path length, minimum clearance, recovery and stale-cue latency, compute cost and all initial failures. Do not inflate a count of hundreds by counting component assertions or replayed variants as completed distinct journeys.

Zero collision for arbitrary unbounded wrong turns, obstacle teleports or uncontrolled pedestrian impact is not physically guaranteeable. Declare the simulated response/obstacle bounds in advance, keep those challenging cases in explicit failure categories, and do not turn bounded simulation results into independent child-travel approval. LLM input/output has no map/position/obstacle/path/control authority; conversation/comfort remains separate.
