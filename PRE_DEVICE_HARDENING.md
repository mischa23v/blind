# Pre-device companion hardening, 2026-10-23

This document supersedes older depth-only startup, central colour sampling and background-admission descriptions. Baseline: primary `63861923f4ff67556e274d284e761ee56f76d901`. This is source/policy hardening, not proof of safe independent child use or completion of the whole product.

## Product contract

The local assistant is a continuous, goal-aware companion, not a collection of scanner modes. Ordinary conversation must work without camera evidence; physical facts must not. Current frames, retained goals, remembered places/items and bounded automatic tools should do the operational work. A child should not navigate feature tabs or guess where to aim before the app checks available evidence. Existing stop, camera-off, privacy, consent and helper setup controls remain.

Core trials remain local and require no external assistant login. Opt-in action-capable external delegation is an essential requirement for the complete adult product, with provider choice rather than a dot-only lock. It is not implemented or verified here. Example future flow: local context → external food-order delegate → clarify merchant/item → approve cart/total/payment → return status → local fresh-sensor pickup assistance. This example is not permission to place an order. A supported bidirectional task/result transport and uninterrupted local sensing are still unresolved; opening a chat app is not equivalent. No private chat scraping, implicit network fallback or new upload is added.

## Closed source gaps

- Fair, single-slot admission alternates eligible passive memory and contextual perception. A repeatedly busy memory producer cannot indefinitely win. Native work retains its slot until completion; expired background producers are disabled for the process, and late callbacks cannot release a successor's slot.
- Camera recovery is bounded to three retries with delays. Lifecycle return does not replenish the budget; explicit restart or a sustained healthy interval does. Permission denial is sticky until an explicit new session. Stop/background invalidates pending retry ownership.
- Frame age uses actual AR capture timestamps, not delayed callback receipt. Stale/future frames cannot renew evidence leases or the camera watchdog.
- RGB camera startup and nonspatial text, light, colour, explicit object/saved-item discovery and familiar-person processing no longer require scene depth or floor calibration. Depth/mobility authority is not fabricated. Colour/currency retain stationary requirements; relevant text may be sampled while moving, subject to freshness/pose and speech interruption checks.
- Familiar capture binds the actual frame, processed-frame freshness, optical pose, session and RGB generation. Live identity hints retain the short freshness limit; labelled snapshot handling remains separate. Nonurgent missing-monitoring warnings no longer discard enrollment drafts. Urgent obstacles/drop/overhead still interrupt.
- A disconnected private audio route holds ordinary speech until explicit restart/unmute. Private-capable speech, including room/route names at mobility priority, uses cancellable synthesis; only provenance-backed independent alerts retain safety transport. Route loss interrupts private-capable active output, and foreground return cannot silently announce names or goals on the speaker. Actual alert-backed hazard/mobility warnings remain available. Native audio-route timing and VoiceOver coexistence still require device acceptance.
- Retained destination/search goals can trigger relevant OCR without an explicit reading command. Token matching avoids substring false matches; unrelated text, unverified money values and physical instructions are not promoted into guidance.
- Colour no longer samples the image centre or chooses a largest/central object. A single isolated foreground mask supplies an eroded interior patch; multiple objects, person overlap, insufficient coverage and ambiguity abstain. The result is anonymous sampled appearance, not proof that it belongs to “this”, an outfit or a pot. Unresolved referents remain retryable rather than falsely completing the task. Current RGB is inspected first; no new manual aiming workflow was added.
- Generic model-requested camera evidence now uses the same RGB context verifier. Stable OCR/appearance records are explicitly attributed captured views with a separate bounded 12-second lease, never current presence. Exact attribution, fresh current pose/session and playback checks permit a complete snapshot utterance without renewing old images. Live identity, currency, object position and physical authority are not relaxed.
- Explicit object search, saved-item lookups and colour checks have logical deadlines and separately owned native slots; a hung native operation cannot stack replacement work. Still-owned stale results settle honestly as unavailable; cancelled or replaced owners remain silent. The old image-model side-hint route is no longer invoked.
- Exact narration hold/resume commands preserve voice/camera and retained context; ordinary speech yields to voice activity. Quiet does not suppress verified hazards. Addressee detection is not claimed.
- Road-crossing intent receives a code-owned response, never model clearance based on a signal, stopped cars, no visible cars or a stored map. Child/default responses require an accompanying adult; explicit adult communication mode still grants no crossing authority. The local audience choice is not verified age or proof of supervision.
- Conversation instructions preserve useful supported next steps for incomplete searches and tentative familiar-person wording. A legacy prompt allowing rough object-distance estimates was removed.

## Evidence and honest limits

Portable production-policy tests and extracted native-source gates are distinct from Apple SDK execution. Synthetic adapters test event/state ownership, not camera recognition quality. The fresh conversational evaluation had 57/60 fully met turns before a general instruction repair; a separate fresh 12-turn follow-up passed 12/12. Four follow-up search continuations asked another person because the supplied packet lacked validated pose/reach/controller evidence. That is safe fallback, not autonomous task completion. One inconsistent original identity-wording rubric was disclosed, not retroactively rescored. A separate seeded 20-episode metamorphic evaluation met 19/20 literal rubrics and 10/10 paired relations; its sole literal miss was silent hold versus a required acknowledgment, although holding was correct. Responses averaged 29 words and reached 46, so brevity/usability remains a real issue. The later road-crossing cases were not part of that frozen model run.

The frozen four-case reference-matcher diagnostic was rerun using existing local images, unchanged references and thresholds, across SIFT/ORB/AKAZE. Each returned two correct experimental SAR labels, zero wrong denomination labels, two abstentions, and one single-note-policy false acceptance. That last result was the correct SAR label in a synthetic SAR-plus-foreign-note collage, not a mistaken denomination. Under a visible-SAR-only contract this can support a candidate SAR label, but it cannot establish one note, absence of foreign money, a total, authenticity or legal tender. The separate native scene gate was not executed. These are previously seen development cases, not an independent accuracy rate, and no improvement is claimed. Cold desktop runtimes are not phone latency.

Existing dataset limitations remain: repeated physical notes/capture families, missing polymer-five coverage and no independent all-condition validation. No new model weights, training or threshold tuning occurred. No executable face embedding weights were present locally, so face Python accounting tests are not a new recognition benchmark. Colour tests use synthetic masks plus diagnostic patches from two existing non-clothing photos; there is no validated outfit/white-versus-cream/pot/chest-camera corpus.

## Remaining backlog, classified

1. **Native integration acceptance:** actual Apple SDK build/typechecking, ARKit/Vision orientation/mask behavior, camera recovery, voice interruption, VoiceOver, hardware permissions, latency, thermal/battery and target phone model execution require Mac/iPhone. Syntax parsing does not close this row.
2. **Recognition resources/data:** an approved production Saudi reference profile and a general object detector are not bundled; existing Debug test assets remain separate. Additional weights/downloads/training are not silently authorized. Face native models and calibrated real look-alike/unknown tests, independent Saudi notes and real colour target/lighting tests remain required.
3. **Target identity and physical execution:** a mask/centre or a generic feature-print match does not establish the requested object, ownership, safe grasp point, body-relative direction or a clear route. Same-frame target association and depth/controller validation remain unfinished capability work, not a unit-test pass. Current code withholds unsupported reach/pickup/navigation directions rather than treating a model sentence as authority. No arbitrary ROI field would close this without an actual verified caller and target association.
4. **Specialized semantic dispatch, next source slice:** a real FoundationModels Tool/@Generable read loop already connects current/captured observation, saved memory, navigation state and clock to typed evidence. Specialized currency/colour/familiar controllers are not yet advertised through that loop; passive capability goal selection remains lexical. The next source task is a bounded typed read-only specialized dispatcher using existing tools, with request/session/goal ownership, failure recovery and exact evidence rendering. It does not require a new dependency or Mac to implement/test policy. Native small-model tool-choice quality still requires device evaluation. This is not marked complete by the current push.
5. **External actions:** provider-agnostic opt-in action delegation is required for the complete adult product, but supported transport, credentials/approval boundaries, results and camera continuity need separate design/verification. Local child testing is not blocked by its absence.
6. **Whole-life readiness:** continuous eligibility does not mean continuous visibility or 24-hour OS permission. Field-of-view misses, occlusion, no light, moved objects, map relocalization and hardware coverage remain real limits. Historical memory is a search lead, not current physical truth. Cooking heat, allergies and sharp objects cannot be inferred safely from appearance alone.

Do not mark these rows complete because the portable suites pass. The next device phase should focus on native model/sensor behavior and integration, while retaining this explicit unfinished product backlog rather than claiming the full vision has shipped.

### Fresh recorded sensor replay

All 84 sensor cases (48 synthetic and 36 conditional runs from 12 distinct real RGB-D stair frames) and six baseline/six dense real-mesh virtual-ray poses were executed against current production policies. Complete results match historical outputs, including known failures. Baseline mesh labels match 4/6; dense labels match 5/6, with unresolved floor-control uncertainty. Calibration-sensitive upward stair runs yield 7/18 obstacles, 10/18 incorrect drops and 1/18 uncertain; downward runs yield 15/15 drops, with three oblique runs unscored. Assumed camera heights and unverified gravity conventions prevent interpreting these as independent recognition accuracy.

The C++ belt threshold sweep specifically recognizes only 8/21 changes in each direction, missing 13/21 each. These misses remain open; no thresholds were guessed against known examples. The real-surface audit refuses unsupported clearance in all 2,783 floor cells; this is not proof every cell is physically blocked. A separately authored café simulation passes 17/17 assertions. Real mesh rays are not an iPhone walk, and authored maps/model selections are not measured household localization or actual language-model execution. These results do not establish safe child mobility.

### Slope classification remains absent

`HazardDetector` is explicitly a level-floor prototype with scalar floor height. It has no uphill/downhill/cross-slope result class; rejecting a sloped calibration fixture is not slope recognition. The belt sweep's 30/45/60-degree values are sensor pitches, not walking-surface slopes. Its raw-range threshold has no attitude or plane geometry. Continuous ramps, transitions, sharp edges, cross-slopes, missing support and body pitch require a separately specified classifier and predeclared tests with verified geometry; changing a height threshold cannot distinguish them. This is open source/design and empirical validation work, not only a Mac setup issue.
