# A01 / E02 — accessible controls and explicit microphone recovery

Source implementation, 2026-10-30. No Apple build, Swift test, microphone, model, audible VoiceOver or physical-device execution was performed for this patch. Tracker IDs refer to `research/tracker-reconciliation-20261028/TRACKER.json`, not the older differently numbered TASKS families. A01/E02 remain open pending native/device acceptance.

## Concrete changes

1. **Terminal microphone recovery is explicit.** The existing `VoiceCaptureRecoveryPolicy` retains a restart hold after terminal failure, exhausted three-attempt recovery, private-route loss or a system interruption ending without resume permission. Cancel, foreground, language change, media reset and automatic answer windows cannot erase the hold. Only the existing explicit `NavigationModel.startConversation` route supplies `explicitlyRequested: true`; permission, offline-recognition, session-generation, OS-interruption and background checks remain in place. Ordinary recoverable interruption/retry behavior stays bounded. The hold is ephemeral, not a saved permission or speaker-identity claim.
2. **Accessible recovery and quiet/resume controls.** An active session whose capture is held now exposes Reconnect microphone instead of only Mute. Mute and End remain available. Conversation controls gain a reachable descriptions toggle with a localized accessibility value; it uses the existing stop/resume functions and neither starts microphone/camera nor restores a cancelled task. The unused older `actions` view was not evidence of actual control reachability.
3. **Ask layout candidate.** The finite Ask screen uses the already used Camera `ScrollView`/eager `VStack` layout and minimum-height button style, with semantic section headers, multiline text, native inline selection, labelled input fields and the exact disabled-camera explanation. There is no size cap, truncation, hidden warning or accessibility-audit exemption. Earlier audit callbacks do **not** establish lazy Form sizing as the cause. Native audit and actual VoiceOver behavior are still required to validate this candidate.
4. **Newly triggered accessibility CI storage is off by default.** Its two existing artifact uploads now require the same explicit source opt-in as the other relevant lanes. Retention remains three days if separately enabled; nothing is deleted. Existing layout/audit commands and failure handling remain unchanged. The shared bounded receipt emitter emits only job/step outcomes for this lane, into normal logs/summary, and reads no image or arbitrary JSON. Build/test output remains in normal job logs. No runner, service, dependency, cache or paid storage assumption was added.
