# Native occupancy adapter protocol (before recorded frame use)

Source: official OctoMap v1.10.0, commit007a0b5b6e4d3bb6c54f2c65a12234e03adcd72f. The 48 original files and license remain unmodified. Source acquisition receipt binds official Git blob SHA1 and local SHA256. No ROS/system install/graphics/OpenMP.

The earlier REUSE_PLAN mentioned upstream `discretize=true`; that is NOT the implemented strategy. It moves endpoints to cell centres before ray tracing. The reviewed adapter instead converts supplied coordinates to the library's Float32 point type, calls native `coordToKeyChecked`, retains the FIRST ACTUAL measured input point per native occupied key, and calls native `computeUpdate` on these measured representatives. Full original native occupied-key equality is checked every scan. Free evidence is therefore a disclosed subset of actual recorded rays, not full-cloud free-space equivalence and not invented voxel-centre rays. Preserve original double-projected input/source evidence and record conversion/association differences in the recorded adapter.

Native occupied-wins within each scan is checked. The wrapper uses the exact upstream free-then-hit `updateNode` operations with lazy=true, followed by `updateInnerOccupancy`. No pruning or conversion to maximum likelihood occurs. Hit/free counts increment once per distinct scan/key; frame indices must arrive exactly0,1,… and cannot repeat. A failed partial insert retires its handle. Native unknown nodes return known=0, NaN score; occupied=0 for unknown MUST NOT mean free. Threshold decisions are delegated to upstream `isNodeOccupied`, not a Python comparison. Defaults are unchanged: hit0.7, miss0.4, threshold0.5, clamps0.1192/0.971. These are mapping weights, not calibrated probabilities of physical safety.

Bulk native keys and keyed queries allow raw Float64 voxel evidence to be associated with the ACTUAL keys used by Float32 OctoMap points. A later map import must not assume a reconstructed raw-cell-centre query is equivalent near quantization boundaries. Unknown or unresolved key association stays blocked.

All endpoints and origins must be finite and within native key bounds. Before ray traversal, the native Manhattan key-distance upper bound plus2 must be strictly below the actual `KeyRay.sizeMax()` capacity. Overlong valid-coordinate rays are rejected, not truncated. Limits:2million input/key-conversion points per call,5million query/export leaves,8192 sequential scans. Native handles require exclusive serial ownership. Python uses an RLock around every call and close because ctypes releases the GIL, and enforces count caps before array conversion/allocation. Copied query/export arrays own their memory.

Unit fixtures cover unknown versus observed free; actual hit; defaults; duplicate pixels versus distinct scan votes; exact occupied-key equivalence across signed/boundary values; actual measured-ray geometry distinct from a voxel-centre ray; occupied-wins; explicit later ray evidence updating an old hit; nonfinite and repeated-frame refusal; native ray-buffer bound; score-preserving export; native key/occupancy equivalence; wrapper count limits. These are library/adapter checks, not real sensing, obstacle detection, small-object/stair detection or navigation trials.

No recorded integration is approved merely by this file. It requires a separate frozen frame/range/ROI/default/SurfaceCell import protocol. Keep the first failed map and all source endpoints/conflicts. Estimated occupancy/free state must never become production physical clearance. The independent FARO evaluator cannot tune fusion parameters, frame selection or routes.
