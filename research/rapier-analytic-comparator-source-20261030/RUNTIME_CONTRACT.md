# Runtime contract — existing managed sandbox, trusted official source

The controls-only launcher executes the integrity-pinned official compat package directly inside the existing managed execution environment. It does **not** create user/network namespaces, change host settings, request elevated privileges, install components or use paid compute. The earlier mandatory-unshare source was never executed or denied; it is superseded and preserved as an unexecuted preparation variant.

The child receives only the fixed allowlisted environment; inherited credentials, proxies, NODE_OPTIONS and loader/preload hooks are absent. Stable `--permission` grants reads only to published packet and acquired package, and writes only to the fresh attempt directory. No child-process, worker, addon or WASI grant is supplied. The worker checks enforce mode, permission API availability, child/worker denial and absence of global filesystem grants before the package load. No operation is attempted merely to test a denial. Input hashes and output accounting supplement these guardrails.

The [official Node permission model documentation](https://nodejs.org/docs/latest-v24.x/api/permissions.html) treats permissions as protection against unintended operations by trusted code, not containment for malicious code. The [runtime permission API](https://nodejs.org/docs/latest-v24.x/api/process.html#processpermissionhasscope-reference) documents `child`, `worker` and filesystem queries. These controls do not independently prove network isolation. The verified compat initialization embeds its WASM and requests no external fetch in this path; the benchmark protocol requests no network activity. We do **not** claim an independently air-gapped process or network-monitoring evidence.

The exact pinned Node binary contains stable `--permission` and an embedded `v24.22.1` string; this is byte-only compatibility evidence, not an executed version or CLI check. The prior `--experimental-permission` spelling is absent from those bytes and is no longer proposed. Runtime records will retain actual `process.version` if execution is later admitted. Any unsupported option or permission mismatch fails without widening permissions or retrying.

Resource limits remain one CPU, 120 aggregate CPU seconds, 180 wall seconds, 1 GiB observed aggregate RSS, 16 MiB aggregate output, Node old-space 256 MiB/semi-space 8 MiB, 104 controller calls across 108 nested control rows. RSS polling is not a hard cgroup bound, and Node heap limits exclude native/WASM memory. No RLIMIT_AS is imposed. Original poses, geometry, profiles, analytic fixture expectations, independent-hazard distinction and no-movement authority remain unchanged.
