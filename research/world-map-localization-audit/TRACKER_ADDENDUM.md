## Required outcomes

- **Correct saved map and floor:** select the exact map/frame/revision and floor, distinguish look-alike rooms and repeated layouts across buildings/floors, and reject ambiguous, stale, unavailable or contradictory matches. GPS/appearance may shortlist; neither establishes metric pose. No match does not prove that the area is new.
- **Measured current position and orientation:** estimate position and camera orientation in the selected map with measured uncertainty. Distinguish camera heading from body/walking heading. A single image or camera trajectory does not establish body heading without a separately validated mounting/body relationship. Unknown body heading withholds body-relative direction commands.
- **Continuous route deviation, including how much:** throughout the journey, measure signed cross-track distance where geometrically defined, along-path progress, camera heading error and separately validated body-heading error, with capture time, uncertainty and reference segment/frame. Use held-out image pairs/sequences to evaluate how accurately these quantities can be estimated; do not merely label the person on/off path. Ambiguous nearby/crossing route segments must not cause progress jumps. Distinguish a supported detected deviation from localization unavailable or too uncertain to measure deviation.
- **Safe connection from current pose to an existing path:** the person need not begin on a saved waypoint. Verify a connector from the current measured support location into the route in the same frame/floor, with body swept-volume, support, clearance, uncertainty and current hazard/coverage checks. Nearest waypoint, straight-line proximity, teleporting/snapping to the path, or a map projection through a wall/obstacle is not a valid connector. If no supported connector exists, retain the goal and report unavailable rather than command movement.
- **Known paths versus progressive unknown areas:** use the existing catalog and restrictions where coverage is established. Accumulate genuinely new observations without treating unobserved cells, mesh holes or discarded anchors as free. Keep unregistered sessions separate. Require measured frame association before merging with a saved building/floor map; do not invent doors, floor links or routes to make coverage connected.
- **Recovery and return:** map/floor change, lost tracking, restart, background, deletion, changed body mount or changed goal retires old output. Restore intent/history only; reacquire current position/orientation and revalidate the connector/route. A successful association of portal endpoints is not proof of the traversed crossing or clearance.

## Frozen held-out localization evaluation

Before running, freeze the map/reference corpus, upstream method/version, calibration inputs, frame convention, selection seed, operating envelope, accuracy/heading/coverage limits and reject criteria. Reuse established localization/registration implementations; do not substitute an LLM location guess. Set limits from the downstream geometric/safety requirements, not after seeing successful results.

1. Select reproducible random held-out queries across mapped rooms, floors, look-alikes, entrances, difficult viewpoints, unmapped areas and transitions. Include failure/low-overlap examples, not only easy images. Keep query captures out of reference training/map construction where evaluating a new visit; disclose any shared scan and correlation.
2. Evaluate separately: **one random image**, **two images**, and a **short causal sequence**. Report exactly what each mode receives. If a mode lacks necessary metric/orientation evidence, its result is unavailable—not a fabricated pose. A longer sequence cannot retroactively make the single-image mode a pass.
3. **Hide query poses and ground-truth transforms from the localizer/controller.** Keep them evaluator-only. Remove metadata/file-name leakage and any ground-truth starting point, floor label, map ID or oracle route seed. Permitted fixed camera intrinsics/calibration and reference-map data must be declared. If measured online odometry is supplied in a separate track, identify its provenance; exported/optimized query poses must not masquerade as live odometry.
4. Score correct map/building/floor identification, false confident matches, ambiguity/rejection, position error, camera-angle error, body-angle error where independently measurable, uncertainty calibration, relocalization time and availability. Continuously score cross-track-distance error, along-path-progress error, heading-error estimates, deviation detection delay, missed deviations and false deviation alarms against evaluator-only truth. Report denominators, rejected/not-evaluable cases and failures. No observed errors in a small sample is not a reliability claim.
5. Starting at held-out **off-path** poses, evaluate the actual current-pose→path connector and resulting route using independent geometric truth. Include walls, furniture, disconnected free regions, thresholds, missing floor support, wrong floors and unknown coverage. An oracle collision veto is evaluator evidence of an attempted invalid action, not successful avoidance.
6. Include deliberate lateral steps, wrong turns, overshoots, camera-only turns, backward movement and localization loss in controlled recorded/replay or rig scenarios. A camera-only turn must not be misreported as a body turn; tracking loss must not be reported as a measured lateral deviation. Test repeated/parallel/crossing path segments and uncertain progress. A proposed return-to-route connector must pass the same current collision/support/coverage checks as initial path entry; never snap to the nearest line or reuse an unchecked straight-line correction.
7. Repeat after loss/restart, map replacement, doorway/floor transitions, moved furniture and body/camera heading disagreement. Delayed callbacks from the old map/session/goal must not revive directions. Test destination retention and blocked return without replaying historical clearance.

Any confident wrong map/floor, unsupported pose/heading, invalid connector or stale-authority revival blocks this gate in the declared domain. Accuracy/availability, measured uncertainty and rejection behavior must meet predeclared limits; an always-reject system is not useful navigation success. Recorded-image evaluation cannot by itself pass live hazard latency, wearer calibration or physical-device safety gates.
