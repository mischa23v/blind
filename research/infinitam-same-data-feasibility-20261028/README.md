## Verdict

Technically plausible **fixed-pose CPU TSDF fusion comparator**, not GPU-only and not a drop-in stock CLI run. Released CPU reconstruction, file-based poses, and CPU marching-cubes output exist. Three practical issues need an audited adapter/build configuration: per-frame calibration, headless CMake configuration, and mesh-allocation bounds. License applicability to this project needs resolving before execution/publication; source inspection alone is not evidence of permission to integrate or run it for a commercial-product research purpose.

## CPU support and real build traps

- [README](https://github.com/victorprad/InfiniTAM/blob/4156547e7f118c3a303d0b3c20f4da2aa3bfc9c9/README.md) explicitly permits building the CPU part without CUDA and describes `InfiniTAM_cli` for offline headless use.
- [`UseCUDA.cmake`](https://github.com/victorprad/InfiniTAM/blob/4156547e7f118c3a303d0b3c20f4da2aa3bfc9c9/InfiniTAM/cmake/UseCUDA.cmake): `WITH_CUDA=OFF` defines `COMPILE_WITHOUT_CUDA`; [settings](https://github.com/victorprad/InfiniTAM/blob/4156547e7f118c3a303d0b3c20f4da2aa3bfc9c9/InfiniTAM/ITMLib/Utils/ITMLibSettings.cpp) select CPU absent CUDA/Metal. Explicitly set `DEVICE_CPU` in the adapter as well. This is actual CPU implementation, not a CUDA fallback stub.
- Stock [Apps CMake](https://github.com/victorprad/InfiniTAM/blob/4156547e7f118c3a303d0b3c20f4da2aa3bfc9c9/InfiniTAM/Apps/CMakeLists.txt) unconditionally adds GUI and CLI. GUI includes `UseOpenGL.cmake`, which calls `FIND_PACKAGE(OpenGL REQUIRED)`. Building only the CLI target does **not** avoid this configuration-time dependency. Disclose a narrowly scoped GUI-disable patch/minimal build wrapper, or obtain the GUI development dependencies even for a CLI-only target.
- Compiler and make are present here; `cmake` is not on PATH. No dependencies were installed. Minimal dependencies are CMake, C++ compiler/build tools, internal libraries; libpng is optional if our adapter reads explicitly defined raw/PGM files instead. No camera drivers, CUDA, OpenNI, or live device required. Modern-toolchain compatibility is untested; upstream declares CMake 2.8 and contains old compiler flags. Use an appropriate pinned CMake or record compatibility-only patches, not unknown third-party setup scripts.

## Exact input adapter

Reuse the **same ordered 265 training IDs** from `open3d-same-data-benchmark-20261028/fresh-run/FUSION_FROZEN.json`; never integrate the 29 excluded images. Preserve frame-ID mapping when making a contiguous file sequence. Reuse original `transformations.json`, not a silently substituted COLMAP pose file.

1. Decode existing PNG depth losslessly. It is axial millimetres, not ray range. [Disparity calibration](https://github.com/victorprad/InfiniTAM/blob/4156547e7f118c3a303d0b3c20f4da2aa3bfc9c9/InfiniTAM/ITMLib/Objects/Camera/ITMDisparityCalib.h) has affine 0.001 scale and zero offset. [Converter](https://github.com/victorprad/InfiniTAM/blob/4156547e7f118c3a303d0b3c20f4da2aa3bfc9c9/InfiniTAM/ITMLib/Engines/ViewBuilding/Shared/ITMViewBuilder_Shared.h) expects signed short and rejects nonpositive / >32000 values. Check unsigned PNG range before conversion; pre-mask depths outside the common 0 < z < 4 m input domain to zero and record counts. No new smoothing or downsampling in this first comparator.
2. Use each frame's `w=738`, `h=994`, `fl_x/fl_y/cx/cy` through `ITMIntrinsics::SetFrom`. Local read-only metadata inspection found **209 distinct focal lengths, 293 cx values, 287 cy values** across all 294 frames. A single calibration file is therefore wrong for this exact benchmark. `ITMViewBuilder_CPU` copies its initial calibration only when it creates the view; update public `GetView()->calib` before subsequent frames, starting the engine with the first training frame's calibration. Alternatively use released view-builder and dense-mapper APIs in a minimal runner. Assert effective calibration each frame.
3. RGB is not needed for the default `ITMVoxel_s` geometry-only representation. Supply a documented dummy RGB buffer if the API requires it; do not claim RGB-assisted reconstruction. If later testing colour voxels, use actual decoded images, correct alignment/calibration, and label that separate experiment.
4. Camera convention: let C be supplied OpenGL camera-to-world. Set InfiniTAM camera-to-world to `C * diag(1,-1,-1,1)` (positive camera Z, image-down Y). `pose_d->SetInvM(...)` accepts that; equivalent modelview is its inverse. Preserve metres and original world origin. Do not apply phone-to-FARO during fusion; use it once in the evaluator only.
5. Released [file tracker](https://github.com/victorprad/InfiniTAM/blob/4156547e7f118c3a303d0b3c20f4da2aa3bfc9c9/InfiniTAM/ITMLib/Trackers/Interface/ITMFileBasedTracker.cpp) accepts per-frame camera-to-world matrices, with explicit element loading; [factory](https://github.com/victorprad/InfiniTAM/blob/4156547e7f118c3a303d0b3c20f4da2aa3bfc9c9/InfiniTAM/ITMLib/Trackers/ITMTrackerFactory.h) supports `type=file,mask=...,initialFrameNo=0`. File failures can be masked by permissive integration defaults: abort missing/malformed poses externally. Safer simple runner: call `turnOffTracking()`, set `GetTrackingState()->pose_d->SetInvM(Ccv)` before every `ProcessFrame`, and assert it did not change. Both are released APIs, but the runner is our adapter. This measures fusion under supplied poses, not SLAM accuracy.

## Parameters, output, and bounds

Freeze two different configurations only if both are wanted: upstream defaults versus matched Open3D scale. Do not conflate them. Upstream defaults are 5 mm voxel, 2 cm truncation, 0.2–3 m frustum; existing Open3D comparator uses 4 cm voxel, 20 cm truncation, <4 m input. A matched configuration would explicitly set voxelSize=0.04, mu=0.2, maxW=100, frustum to admitted positive depths through 4 m, bilateral filter off, swapping disabled, basic mode, CPU. Engine integration rules still differ; this is not a byte-equivalent algorithm. Freeze exact near-boundary treatment before execution and retain default max-weight semantics.

[Hash constants](https://github.com/victorprad/InfiniTAM/blob/4156547e7f118c3a303d0b3c20f4da2aa3bfc9c9/InfiniTAM/ITMLib/Objects/Scene/ITMVoxelBlockHash.h) allocate 0x40000=262,144 blocks ×512 voxels. The nearby comment incorrectly says 2^17; use the actual constant. With the default short-SDF/byte-weight voxel and typical 4-byte layout that is **512 MiB** voxel storage alone; confirm `sizeof` at build time. Other hash/visibility/image/tracker buffers increase memory.

**Do not use stock `SaveSceneToMesh` under the current memory envelope.** [ITMMesh](https://github.com/victorprad/InfiniTAM/blob/4156547e7f118c3a303d0b3c20f4da2aa3bfc9c9/InfiniTAM/ITMLib/Objects/Meshing/ITMMesh.h) defaults to 134,217,728 triangle slots: at 36 bytes/triangle, **4.5 GiB** before scene overhead. It supports a `maxTriangles` constructor. Use released CPU mesher with an explicitly budgeted buffer (e.g. 2 million slots =72 MB), and **reject saturation**. The [CPU mesher](https://github.com/victorprad/InfiniTAM/blob/4156547e7f118c3a303d0b3c20f4da2aa3bfc9c9/InfiniTAM/ITMLib/Engines/Meshing/CPU/ITMMeshingEngine_CPU.tpp) silently stops incrementing at maxTriangles−1, overwriting the last slot; a saturated mesh is not a successful complete reconstruction. Also reject voxel/hash-pool exhaustion; record allocator high-water marks rather than assuming skipped allocations are benign.

Export OBJ/STL via released `ITMMesh`, or a lossless numeric PLY adapter. CPU mesher multiplies vertices by voxel size, retaining original-world metres. Feed the unedited mesh to the existing common 29-frame ray evaluator with the same intrinsics, integer-pixel rays, phone-to-FARO registration and all missing-hit denominators. No floor flattening, gap filling, path carving, mesh simplification, or reference-based fitting. New hashes/receipt required; never overwrite the completed Open3D result. No measured-reference mask means these scores still cannot establish actual false-clear/false-block or child-safety rates.

Proposed resource reservation, **not a measured prediction**: one CPU worker, staged small-frame smoke test, 2 GiB RSS abort bound for reconstruction with capped meshing, 1 GiB incremental disk target if inputs are reused, separate existing evaluator budget. Runtime/build size unknown until tested. Avoid full raw duplication: 265 ×738×994×2 depth bytes alone is about 389 MB. Stop early on bound violations, pool exhaustion, failed unit fixtures, or calibration/pose mismatch; no results then.
