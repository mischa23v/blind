# J01 selected prebuilt build/source receipt layer

This is an additive overlay on reviewed J01 manifest `6038c57204ca96482722b40a647156fc02748fd4a72c07d732e9fc8dc3a42e43`. That original packet is unchanged. This overlay strengthens its prebuilt wrapper: it refuses execution without an independently trusted build-receipt digest, and verifies selected descriptor/app/test bytes before launch and after observation. The earlier README's claim-only path is historical; it is no longer sufficient to run this overlay.

## What is verified, and what is NOT

The recorder **does not build or run anything**. Its `begin`/`finish` commands reuse exact existing `tools/ci/export-native-unit-statuses.py:provenance` plus its exact reviewed lock-file parser. These enforce expected workflow SHA equals actual Git HEAD, clean tracked source, no unexpected untracked source in existing CI scopes and only existing reviewed dependency-lock exceptions. Before/after source and CI run/job identity must match. Finish additionally requires an actual successful `xcodebuild build-for-testing` command receipt from the surrounding reviewed build job.

It records full regular-file inventories of the selected app and hosted test bundles, their executable bytes/modes, Info.plists and descriptor hash. File/directory symlinks, any parent-traversal components, canonically escaped paths, unsupported descriptor placeholders, missing files, unknown targets and oversized input fail closed. Hashing checks regular-file type before opening and after obtaining a no-follow/nonblocking descriptor, then uses bounded streaming reads and file-change checks. Regular filesystem I/O can still block; the time check is observational, not a hard syscall deadline. Both executable headers must be Mach-O; this is a format sanity check, **not proof the synthetic tests built an executable**. Count/size limits:8192 files and8192 directories per bundle,256MiB/file,2GiB combined selected bundle data,4MiB descriptor,8MiB receipt. Legitimate builds exceeding bounds or using unsupported layouts need a separate reviewed change, not bypass.

**A JSON receipt is not self-authenticating.** The generated receipt explicitly says untrusted. Environment variables and a claimed command are not independent proof of CI execution. The integration/review owner must obtain the receipt digest from authenticated, reviewed CI build evidence and independently authorize that exact digest. Do not compute `trusted_build_receipt_sha256` from an arbitrary downloaded or caller-provided receipt and call it trusted. No approved native receipt exists from this source-only work.

Only after that external trust decision does `sourceAttestation.verified:true` mean: **selected prebuilt bytes match the externally trusted clean-source build receipt**. It does not mean runtime-loaded binary attestation, signed provenance, model correctness, test success, physical safety or completed journeys. `runtimeLoadedBinaryVerified:false` and the native test's original claim-only attestation remain in the output. Runtime/system frameworks and model assets are outside this selected-bundle identity scope. This is not hardened against a malicious concurrent writer; pre/post checks detect ordinary mutation but do not remove the time-of-check/use interval. Use the reviewed isolated build workspace.

## Exact future build interface (no execution during preparation)

On the existing authorized disposable public Apple CI job, using a complete clean checkout (including the existing lock parser):

1. Before the reviewed build, run `python3 -B research/j01-hosted-app-adapter-20261030/build_attestation.py begin --repo . --out <fresh-outside-repo>/begin.json`.
2. Run the separately reviewed default unsigned simulator **build-for-testing** command. Do not change normal jobs or introduce model downloads/paid runners. The surrounding shell captures its actual argv and exit status as `{"argv":[...],"exit_code":0}` (nonzero exits remain failures).
3. Only after that command completes, run `... build_attestation.py finish --repo . --before <begin.json> --command <actual-command.json> --build-root <Build/Products> --descriptor <relative.xctestrun> --out <fresh-receipt.json>`.
4. Review real build/job provenance and approve the resulting digest externally. Receipt-only producer controls or a fabricated fixture receipt cannot satisfy this trust step.

Required CI context is `GITHUB_ACTIONS=true`, exact repository `mischa23v/blind`, real `GITHUB_SHA`, run ID/attempt/job/workflow reference. No environment dump, credentials, signing identity or account access is requested. Receipts contain public source/build-relative filenames and bounded build-command metadata; keep outside public logs unless reviewed. This packet adds no workflow, upload or paid storage.

In addition to the existing J01 config fields, the prebuilt wrapper now requires `build_root`, `build_receipt_path`, and **independently approved** `trusted_build_receipt_sha256`. Descriptor selection must be inside that build root. It validates at initial selection, immediately before launching the explicit test, and again before exporting the result. Native output's echoed commit is retained only as a claim; the wrapper adds the separately checked artifact receipt evidence. Any missing trust, byte change or invalid receipt refuses execution/result export. The existing55-second wrapper observation budget now starts before identity checking, with each verification also capped at20seconds checked between bounded reads; a slow scan leaves less native time or fails closed. Blocking individual filesystem/native calls are not hard-preempted. Original log bounds, fresh retained attempt directory, explicit ephemeral-simulator flags and three-script allowlist remain unchanged.
