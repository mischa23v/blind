# Buffered runtime diagnostic validity

The earlier phase experiment's first attempt failed 17/17 runtime tests, followed by four 17/17 passes. Main checkpoint 28 subsequently failed three runtime tests. Those failures are retained. Earlier phase/IO callbacks synchronously printed inside timed execution, so their measured intervals may be observer-perturbed; printing is not proven to have caused the failures. The existing onChange fulfillment closure itself did not print.

This test-only repair uses one bounded metadata buffer per XCTest instance. Every RuntimeIO (including the default installed helper) and every nested/restored runtime phase callback captures that same buffer. NSLock protects a 512-record ring with at most 2,048 characters per record. No global recorder, task hop, sleep, production priority change, or timeout increase is introduced.

All test diagnostic stdout now occurs in an XCTest teardown block after the test body and its waits. The buffer closes and snapshots while locked, then releases its lock before output. It emits dropped-record counts. Post-teardown events are explicitly marked uncaptured and silently discarded; they never print into a later test. Timing overhead from string creation and locking remains, so this is not observer-free measurement or proof of any root cause. XCTest's own failure reporting is unchanged.

All 17 test names, assertion lines, three-second fulfillment, and onChange condition/fulfillment are preserved. The production runtime is unchanged. Existing structural contracts now require buffered metadata instead of synchronous prints, retaining payload-negative checks. The failure extractor also retains the buffer's drop/late-event marker.
