# Robot/vacuum implementation-transfer audit — pinned addendum

2026-10-29. Supplements, not replaces, `README.md`. Five upstream source revisions were resolved through GitHub read-only APIs; `SOURCE_PINS.json` records exact source URLs. These are **research pins**, not dependency changes or proof of a passing build. No tests, builds, installs, model downloads, spending or repository/ref writes were performed. Local coordination evidence only was written. Fusion mathematics belongs to the separate accuracy-methods investigation; this audit concerns concrete robotics integration contracts.

## Findings that change the adoption decision

1. **OctoMap raycast failure is ambiguous.** `castRay(false)` can mean unknown space, maximum range or bounds—not observed free. Use occupancy lookup and terminating condition, not a Boolean “no obstacle” shortcut.
2. **Nav2's hazard watchdog is command-driven in this pin.** `CollisionMonitor::process` is invoked from the velocity subscription, not a standalone phone timer. A phone port needs a sensor/clock-driven loop; copying a timeout function without scheduling it leaves a silent gap.
3. **The selected Nav2 release does not have every rolling-document feature.** Jazzy 1.3.14 has scan/pointcloud/range/polygon sources in the inspected factory; no costmap-source branch. Do not import rolling defaults/features into a pinned-release claim.
4. **Docking can deliberately accept a static target/proximity surrogate.** Without external detection, `getRefinedPose` accepts the stored pose; `isDocked` can return proximity or stall, and `isCharging` may delegate to it. These robot configuration options are not human arrival verification.
5. **Active-view source has a transfer hazard.** `VoxelTypeEvaluator` switch cases lack `break`: free/occupied gain values accumulate when nonzero. Default zero free/occupied weights obscure this. Any changed gain definition needs an independent small oracle before reuse.
6. **A named elevation-map test is effectively empty.** `ElevationMapTest.cpp` contains a test whose setup/body are commented out. Other input/postprocessing/statistical tests exist, but their presence does not establish end-to-end floor uncertainty correctness.

## A. Occupancy evidence and support — first integration boundary

**Pin:** OctoMap v1.10.0, `007a0b5b6e4d3bb6c54f2c65a12234e03adcd72f`; New BSD library. Not selected merely because it is newest: fixed release/source enables comparison.

**Inspected API:** [`OccupancyOcTreeBase.h`](https://github.com/OctoMap/octomap/blob/007a0b5b6e4d3bb6c54f2c65a12234e03adcd72f/octomap/include/octomap/OccupancyOcTreeBase.h): `insertPointCloud(scan,sensor_origin,...)`, `computeUpdate(...,free_cells,occupied_cells,...)`, `castRay(...,ignoreUnknownCells=false,...)`. The supplied-origin requirement makes calibration/pose provenance indispensable. `discretize` changes update behavior; freeze it rather than quietly treating it as a harmless optimization.

**Evidence:** [`test_raycasting.cpp`](https://github.com/OctoMap/octomap/blob/007a0b5b6e4d3bb6c54f2c65a12234e03adcd72f/octomap/src/testing/test_raycasting.cpp) explicitly checks unknown boundaries, range termination and occupied hits. Tests exist for changed keys/scans/IO too; none executed here.

**Minimal transfer:** a C++/Swift boundary accepting measured rays and returning `{state,sourceTime,frame/mapRevision}`; separate measured support ledger. Unknown remains a first-class state. A downward floor hit is positive support only within calibrated geometry/uncertainty bounds; a body-volume free ray does not prove support beneath it. No established OctoMap API supplies the whole human support/head/drop policy—this is the minimal domain adapter requiring tests.

**Experiment:** Coffee foreground-occlusion witnesses W2/W7/W0 versus W6 floor ripple, with the original 350 depth frames and exact transforms. Use the existing held-out 38-frame/FARO evaluation only as oracle, not as mapper input. Count which unknown cells become observed-free via actual rays versus unjustified mesh-hole filling. Freeze original witness coordinates and body/foot bands. Gate: no added accepted route through an unknown support/body cell; report how many genuine blocked paths recover, not just rejection rate.

## B. Metric clearance and live hazard interruption — separate modules

**Metric pin/API:** same OctoMap release, [`dynamicEDTOctomap.h`](https://github.com/OctoMap/octomap/blob/007a0b5b6e4d3bb6c54f2c65a12234e03adcd72f/dynamicEDT3D/include/dynamicEDT3D/dynamicEDTOctomap.h), New BSD: constructor sets bounds/max distance/unknown policy; `update()`, `getDistance()`, `getDistanceAndClosestObstacle()` and error sentinels. The released `exampleEDTOctomap.cpp` demonstrates integration, **not an independent exactness test suite**. Dense bounded array memory must be measured. Keep already prepared native EDT work primary; this is an alternative upstream contract, not permission to duplicate it.

**Hazard pin:** Nav2 Jazzy 1.3.14, `58e4019eb149ed4387938d9cd13f38659b86f754`, Apache-2.0. [`source.cpp`](https://github.com/ros-navigation/navigation2/blob/58e4019eb149ed4387938d9cd13f38659b86f754/nav2_collision_monitor/src/source.cpp) `Source::sourceValid` checks age; timeout zero disables the check. [`collision_monitor_node.cpp`](https://github.com/ros-navigation/navigation2/blob/58e4019eb149ed4387938d9cd13f38659b86f754/nav2_collision_monitor/src/collision_monitor_node.cpp) converts failed enabled source reads to STOP when timeout is nonzero. [`sources_test.cpp`](https://github.com/ros-navigation/navigation2/blob/58e4019eb149ed4387938d9cd13f38659b86f754/nav2_collision_monitor/test/sources_test.cpp) covers outdated, wrong-frame and incorrect data, time shift and pointcloud minimum range. No CI pass asserted.

**Minimal transfer:** reuse audited distance library behind existing admission mask and continuous route oracle; preserve all margin units and conservative cell-boundary handling. Independent hazard evaluator receives current depth/body-relative motion and publishes an urgent evidence event, not `cmd_vel`. Give it an independent deadline/watchdog, future-timestamp rejection, monotonic clock handling and no-motion sensor checks—these are adapter obligations, not claims about upstream behavior. Keep it outside LLM/narration budgets.

**Experiments:** native Apple corner fixtures and existing additional fixtures under identical geometry/endpoints/oracle; rotate/translate grid origin and sweep continuous edges to expose aliasing. Coffee/Koivu fixed-map routes then evaluate map-source errors separately. Replay original chronological frames with labeled delivery-delay/drop/pose-reset injections; these measure software freshness behavior, **not real moving-obstacle detection**. Gate: zero oracle margin intrusion, no stale positive-clearance event, and nonzero completed valid routes. Future live adult chest-phone trial must measure sensing-to-cue latency and human reaction envelope; no robot braking formula proves it.

## C. Floor and pose uncertainty — reference, not adopted stack

**Pin:** ANYbotics/elevation_mapping `f4b082c64a3e660980da53b33c7936a8f2a2ea22`, BSD-3-Clause, maintenance discontinued. [`RobotMotionMapUpdater.cpp`](https://github.com/ANYbotics/elevation_mapping/blob/f4b082c64a3e660980da53b33c7936a8f2a2ea22/elevation_mapping/src/RobotMotionMapUpdater.cpp) exposes `update(map,robotPose,robotPoseCovariance,time)` and propagation of vertical/horizontal uncertainty. Sensor processors are separate modules, so a perfect-sensor configuration cannot stand in for calibrated iPhone depth.

**Test caveat:** [`ElevationMapTest.cpp`](https://github.com/ANYbotics/elevation_mapping/blob/f4b082c64a3e660980da53b33c7936a8f2a2ea22/elevation_mapping/test/ElevationMapTest.cpp) has no active assertions. This resolves the earlier browser cache miss: test directory exists, but its headline map test is not validation. No upstream passing run verified.

**Minimal transfer/test:** expose height/variance/support-count as auxiliary layers, never substitute a single elevation surface for the full 3-D map. On Coffee W6 and Koivu flat floor use the same train/held-out split to compare false floor rejection and reference-height residuals; stratify true discontinuities separately. Pose perturbations are labeled synthetic. Native Apple step/head fixtures reject smoothing across an actual drop or loss of an overhang. Calibrated covariance and real drop sequences remain blockers. Detailed weighting/propagation choices deferred to the fusion/math audit, avoiding duplicated implementation.

## D. Saved return routes and restart recovery — preserve existing SLAM

**Pin:** RTAB-Map `a4e7f13522722878dea3f07e8fd082291e72eb49`, the full commit resolved from the project's prior selected short pin; BSD-style core with separately audited optional dependencies. [`Rtabmap.h`](https://github.com/introlab/rtabmap/blob/a4e7f13522722878dea3f07e8fd082291e72eb49/corelib/include/rtabmap/core/Rtabmap.h) provides `init(parameters,databasePath)`, `process`, `close`, `setInitialPose`, `getLastLocalizationPose`, `triggerNewMap`. [`Parameters.h`](https://github.com/introlab/rtabmap/blob/a4e7f13522722878dea3f07e8fd082291e72eb49/corelib/include/rtabmap/core/Parameters.h) exposes `Mem/IncrementalMemory`, `Mem/LocalizationReadOnly`, `RGBD/StartAtOrigin` and odometry-cache validation settings.

**Critical contract:** startup may assume last saved pose or map origin; an initial pose is a prior, not a fresh match. Read-only localization has documented memory-management/disjoint-session restrictions. Retain map/keyframe association and evidence of accepted correction; do not use “pose returned” alone as localization success. The pin's [iOS workflow](https://github.com/introlab/rtabmap/blob/a4e7f13522722878dea3f07e8fd082291e72eb49/.github/workflows/ios.yml) builds an unsigned app using prebuilt dependencies; it is not an on-device localization test.

**Docking reference at Nav2 pin:** [`simple_charging_dock.cpp`](https://github.com/ros-navigation/navigation2/blob/58e4019eb149ed4387938d9cd13f38659b86f754/nav2_docking/opennav_docking/src/simple_charging_dock.cpp) `getRefinedPose`, `isDocked`, `isCharging`; [`tests`](https://github.com/ros-navigation/navigation2/blob/58e4019eb149ed4387938d9cd13f38659b86f754/nav2_docking/opennav_docking/test/test_simple_charging_dock.cpp) cover battery, stall, staging, refinement and transform failures. Borrow reacquisition/timeouts and staged approach only. Reject static-pose/proximity fallback as destination recognition.

**Minimal transfer:** persist keyframe/map-relative route history, not a replay of turn commands. Gate restart and each resumed segment on accepted localization, map version, current body/support evidence and heading uncertainty. Loop closure must transform/invalidate route coordinates. Endpoint semantics, endpoint localization and clear approach are three checks.

**Experiment/gap:** existing Koivu/Coffee supplied poses can test frame/map consistency and route replay mechanics only. Reversing file order is not a physically recorded return journey or SLAM validation. A real outbound/return sequence, changed furniture/door, phone restart/displacement and independent pose truth are needed to assess relocalization, wrong-place matches and arrival. Until then mark this lane **not demonstrated**, not failed or solved. SLAM Toolbox's laser pose-graph pattern offers no advantage sufficient to replace the existing phone-compatible adapter here.

## E. New-area observation selection — bounded experiment, not exploration mode

**Pin:** mav_active_3d_planning `11634e8325480ce5da36a78b23b917347c973613`, BSD-3-Clause. [`SimpleRayCaster::getVisibleVoxels`](https://github.com/ethz-asl/mav_active_3d_planning/blob/11634e8325480ce5da36a78b23b917347c973613/active_3d_planning_core/src/module/sensor_model/simple_ray_caster.cpp) stops at occupied cells but projects through unknown cells; this is predicted information gain, **not measured visibility**. [`VoxelTypeEvaluator::computeGainFromVisibleVoxels`](https://github.com/ethz-asl/mav_active_3d_planning/blob/11634e8325480ce5da36a78b23b917347c973613/active_3d_planning_core/src/module/trajectory_evaluator/voxel_type_evaluator.cpp) has the fall-through issue noted above. Camera-model/trajectory sensor abstractions and bounded volume provide a concrete transfer boundary. Build workflow is a build recipe, not correctness or present passing CI evidence.

**Minimal transfer:** expose occupancy queries and calibrated camera pose/FOV; evaluate only permitted viewpoints from already supported positions. Add corridor-weighted scoring as a separately tested adapter. Predicted rays through unknown must not mark cells free before capture. The original MAV motion generator/controller is excluded.

**Experiment:** choose equal-budget subsets from the **training** Koivu 265 or Coffee 350 frames; compare fixed-rate, naive unknown-count and corridor-focused selection against held-out 29/38 views. Do not tune on held-out views, let candidate selection see future depth, or let reference geometry certify candidate movement. Disclose prerecorded candidate availability and score coverage/false-free/hazard recall per selected frame. This can assess information selection, not whether a person can execute the prompt or whether online exploration works. Live-only gates include prompt execution, camera/body coupling, unseen hazards, recovery and actual forward progress.

## Shared no-overclaim rule and hardware boundary

Vacuum near-floor IR cliff sensing, broad/360 lidar on some models, dock beacons/markers, rigid extrinsics and controlled motors are hardware capabilities, not algorithms bestowed on a chest phone. The transferable pieces are evidence states, reacquisition, uncertainty propagation, cost/clearance separation, and independent freshness checks. No-motion/unknown cannot count as navigation success; a previous path cannot count as present clearance. No numerical improvement is claimed from this source audit.

**Recommended sequence:** (1) establish observed/support state contracts in existing mapping evaluation, (2) use current native EDT evidence plus independent route oracle, (3) define/replay the freshness hazard loop, (4) evaluate floor uncertainty with fusion worker, (5) verify existing saved-map recovery before return guidance, (6) compare targeted view selection only after preceding gates. This improves the whole system without implementing every robotic feature.
