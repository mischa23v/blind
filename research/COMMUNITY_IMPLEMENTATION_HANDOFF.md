## What is connected

- Places → Community maps: enter a public GitHub `owner/repository`, list release assets, filter names/tags, download a `.blindplace.json` for review, import from Files, save offline, inspect rooms/connections/coverage and contributor review claims, remove a revision, and explicitly select a compatible route revision. Downloads do not change a route or establish current location.
- `PlacePackage` is a bounded JSON envelope around existing `IndoorMap`/`RoomLayout` types. It validates explicit floors, frame IDs, room references, connections, units, revisions, attribution, source dates and review scope. It is **not IMDF**, a SLAM implementation or proof that supplied geometry is correct. It does not infer a door from adjacency. Separate coordinate frames cannot be merged into the existing single-frame route adapter. Explicit floor-transition descriptions can be previewed, but cross-floor point-route edges are rejected until a transition-capable navigation adapter is verified.
- The library keeps immutable, hashed canonical JSON files using Foundation file APIs and CryptoKit SHA-256. Network byte limits are enforced while streaming; downloads use an ephemeral URLSession without cookies or credentials, HTTPS host/redirect restrictions, timeouts, cancellation and the release checksum when available. A hash validates bytes, not contributor identity or physical accuracy. Original publisher bytes and canonical stored bytes can have different hashes.
- A loaded community route retains its source package/revision. User keep-out edits mark that private route copy as modified, remain visible in Routes and cannot be repackaged under the unchanged community revision/review claims. The saved community package itself remains immutable.
- Cache limits: 2 MB/package, 100 valid installed revisions, 40 MB total contents; inventory enumeration refuses more than 200 files. Corrupt files are excluded and shown separately; valid maps remain available. Removing a damaged hash-named file requires an explicit action before redownloading it. A cancellation after an atomic save may leave the complete saved revision present; Refresh reconciles the inventory. No partially written file or preview becomes an active route.
- Authoring exports an explicitly reviewed draft from the existing authored route map. Imported community routes cannot be rebranded by dropping their source package. Full existing packages preserve attribution. Preparing a public copy changes its revision and clears old review claims. Export includes only the package, not the GRDB store, family records, pictures or dialogue. Free-form map text may still contain personal information: the user must review it. No repository creation, publication, authentication, star rating, withdrawal or private backup is implemented here.
- Settings → Interests and preferences: explicit interests/shopping/food/description preferences, up to 16, saved through the pinned GRDB adapter, with removal and visible write failures. Rich local images, photo relay context and local evidence-ID selection receive these hints. Current questions/goals take priority. Changing preferences cancels pending narration. The public map exporter does not read preferences. Inferred habits and user-reviewed learning (M09) remain open.
- `LocalImageAssistant` uses Apple's documented Foundation Models `LanguageModelSession.respond` and `Attachment` image API. The opt-in compile flag `BLIND_APPLE_MULTIMODAL` requires an iOS 27 SDK and runtime availability. The default project keeps the existing Vision/known-evidence fallback. This is an adapter to Apple's runtime, not a new vision/inference implementation or a claim of model reliability. It has no automatic cloud fallback.
- The image prompt includes the question, ongoing goal/dialogue, selected historical room inventory and interests. It asks for useful social/environment/choice information while distinguishing uncertainty. It grants no map write or routing authority. Existing tracking, age, turn/displacement, goal, map-revision, sensor, preference-revision and word-budget checks run before speech. Prompt instructions alone cannot guarantee truthful descriptions; actual image evaluation is still required.

## Remaining connections

Before transfer the user supplied a separate Sol report. [Its reviewed additions](SOL_IDEAS_REVIEW.md) and eight scenarios are now recorded. Framing/last-seen/coverage prompt refinements do not implement object memory or change detection. No tests were run for these refinements.

This library is a repository browser and offline place preview, not a vicinity/search service. Reviews are unsigned contributor claims, not authenticated verification. It does not yet package ARWorldMap/RTAB-Map databases or meshes, establish cross-device localization, feed a downloaded building hierarchy into live assistant context, publish updates, implement ratings/report moderation, or back up personal memory. The existing route adapter remains a prototype requiring separately established alignment. Do not imply these are supplied by the JSON envelope.

Native API compatibility, all new tests, full English/Arabic status localization, VoiceOver behavior and end-to-end scene truthfulness remain unverified. Supported account sign-in/Dot, family identity/tracking, temporal facts, delivered-information history, complete routing and child-readiness gates remain open in TASKS. The latest source is substantial progress, not the completed product.
