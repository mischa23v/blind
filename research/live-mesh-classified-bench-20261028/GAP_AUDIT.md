## Smallest justified implementation increment

The existing explicit classified83 API makes a **new classified bench consumer** a small, reviewable increment. Independent review confirmed that83/75 can return an otherwise usable candidate from retained old tiles after gaps; the new consumer therefore refuses all incomplete-delivery/unknown-coverage results at callback and `isCurrent`, without changing frozen libraries. The queued-floor/refused-removal regression exercises that distinction as an authored native fixture. This folder implements it without changing the historical proposal. It does not pretend that a policy switch completes app wiring, whole-room geometry inspection, localization or physical clearance.

Next app work is specifically an exclusive diagnostic lifecycle owner, bounded geometry snapshot/registration display and native evidence collection—not a replacement SLAM/planner. See `ACTIVATION_HANDOFF.md`. Geometry correctness, retained hazards and truthful unknowns precede useful collision-checked paths; missing sensors must not be replaced by LLM movement instructions.
