# Strict endpoint admission — separate opt-in diagnostic

This adds no app activation and leaves the default `legacyNearestProjection`
behavior and original49a/b1 reports unchanged. The strict policy checks BOTH
requested endpoints with released Detour `findNearestPoly(..., isOverPoly)` before
calling the unchanged legacy path function. It refuses horizontal substitution;
it does not prove support, current coverage, physical clearance or arrival.

## Fixed native comparison

- Same25 already executed requests and9 explicitly not-run journey stages as the
  prior contour experiment. Same exact two-public-SHA packed routing attachment,
  source boxes, body profiles, margins, original endpoints, geometry and oracle.
- One compiled adapter and one fixed `.5` contour configuration. Only endpoint
  admission differs. Initial body/margin collision is scored BEFORE either query.
- Legacy output must reproduce49a exactly. Accepted strict outputs must match
  legacy path/projection bits and collision outcomes. Both policy outcomes remain
  in the result even on mismatch; interpretation is then explicitly inconclusive.
- Admission is non-vacuous: among the11 successful baseline corridors, independent
  legacy `found/isOverPoly` receipts must predict exactly3 known rejections and8
  retained strict corridors. Every pair is checked; rejecting all queries fails.
  Refusals require both matching typed receipts, zero route status/completion and
  no route points. Both retained corner profiles must still show margin contacts.
- Rejected strict rows retain initialized endpoint-association receipts and
  original initial contact evidence. They never manufacture a route/arrival.
- Vertical association remains visible and its connectors remain collision-scored.
  The two hall-corner margin contacts are expected to remain unresolved; no radius,
  margin, tolerance, source geometry or oracle weakening is included.

`INPUT_PINS.json` intentionally retains the already verified capture provenance
schema from the contour experiment. It binds b1source/run40780118332, original
attachment digest, and a distinct parsed-JSON digest. No capture is synthesized.
`SOURCE_PINS.json` binds this new source candidate independently; the historical
contour source pins are not updated or disabled.

## Tests and limits

`cabi_tests.cpp` executes actual upstream plane builds, accepted exact path parity,
vertical association, outside start/goal, missing polygon, upstream on-edge rules,
and bounded malformed/null argument refusal. It checks all available receipts and
route flags initialize deterministically; a rejected admission emits no points.
The Apple runner compiles/executes this before the25-request comparison.

`SavedRoomStrictEndpointTests.swift` separately exercises the public Swift runtime
and actual Bedroom3 export/initial collision oracle in hosted iOS XCTest. It does
not replace either historical route suite or claim their corner failures fixed.
Those hosted tests and this macOS probe remain native-pending until actual receipts
are reviewed. Linux C++ checks are reported separately, never as Apple validation.

The public exact-repo/branch workflow uses standard `xcode-27`, installed Xcode27.0,
one compiler at a time, bounded input/output and300-second total runner deadline.
No install, network dependency, Docker, new upstream algorithm or paid runner.
Only bounded text/JSON evidence is uploaded, not executables/objects/archives.
