## Evidence gates

`evidence.py` is source/receipt/image collection, not a native-command lifecycle runner. Small Git metadata queries use their enclosing GitHub step limit. `--porcelain=v1 -z --untracked-files=all` prevents the old collapsed-directory ambiguity. All tracked source must remain unchanged. The only allowed post-run untracked file is the exact generated `Package.resolved`; initial metadata must be absent. Reuse the reviewed pure dependency parser, while retaining this experiment's stricter schema3, canonical URL and 16 KiB cap. Its validity is recorded independently of source status. Unknown files, wrong pins, duplicate keys, symlinks, malformed or excessive metadata fail closed.

Reuse the unchanged strict endpoint receipt parser. Each accepted endpoint must start/pass exactly once, never skip/fail, report the exact requested runner category, all three content roles and one `footerEnd ... endVisible=true`. Missing or interrupted execution cannot become a pass.

Always attempt each bounded export after source validation, including after native failure. The pinned exporter selects only the four authored roles into private staging. The previously reviewed pure publication gate is reused without its old lifecycle runner: preflight exact names, regular files, PNG signatures and aggregate **8 PNG / 24 MiB** before atomic publication. Earlier accepted images remain if the next endpoint fails. Final collection rechecks the exact eight-file set and hashes; failure still preserves partial evidence without declaring success. Raw xcresults, full logs and intermediate attachments are not uploaded. Bounded synthetic diagnostic summaries and JSON receipts have a **128 KiB per-file / 1 MiB combined** cap. Artifact retention remains 3 days.

Each endpoint reports its native, receipt, category and image status independently. A verified Large endpoint remains passed if AX5 is missing, interrupted or failed; available images do not turn a native failure into a pass. `not_run_due_to_predecessor` additionally requires the explicit serial failure-branch witness to match the predecessor's retained failure and have no conflicting successor execution evidence. The overall job still requires before/after source and tooling verification, all relevant GitHub step outcomes, both endpoints passing, and the global exact-eight-image/24 MiB gate. Source failure, failed export, absent footer-end image, malformed receipt, interrupted step or changed image hash prevents an overall endpoint pass. Export failure receipts do not require a simulator ID.
