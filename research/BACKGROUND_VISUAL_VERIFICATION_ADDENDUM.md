# Image-grounded independent answer checks — design and audit addendum

2026-10-27. **Research/design only; not implemented, tested, device-verified or release-ready.** Read-only audit of public `mischa23v/blind` at `106cc2ad9565513af578d9325110213216e8cc39`. No app edits, provider calls, private images, model downloads or builds. Root task owns any tracker integration/publication. These are backlog notes from iPhone testing, not a diversion from current mapping/localization work or authorization to implement a checker now.

## Decision and user intent

The proposal is sensible: a narrowly tasked second agent checks actual visual evidence instead of asking the answering model to reconsider its own prose. It can catch cases where language priors or remembered descriptions dominate the photograph. A separately prompted invocation may help even with the same underlying model, but it is not an independent sensor and its errors can remain correlated. Different models can share training biases or both miss an occluded person. No guarantee of truth follows from agreement.

Adopt **independent evidence assessment then claim comparison**, not “confirm that this answer is right.” Keep existing source-bound admission, privacy, cancellation, speech ownership and coded hazard authority. Do not introduce an unconstrained parallel agent runtime.

A fast lane can give short, nonactionable conversational output while background checks run. It cannot confidently assert an unverified physical fact and rely on later correction. Door state and whether a chair is free can directly affect walking or sitting even if no command is spoken. Such action-relevant claims require adequate fresh target-specific evidence before assertion; otherwise say plainly “I can't confirm whether that chair is occupied” or “I can't confirm whether the door is open.” “Probably” is not verification. A verified visual door-state answer still does not certify a clear passage or authorize movement.

## Primary research, checked 2026-10-27

- **Woodpecker**, Yin et al., [paper v2](https://arxiv.org/html/2310.16045v2), [authors' source](https://github.com/BradyFU/Woodpecker), [inspected README](https://raw.githubusercontent.com/BradyFU/Woodpecker/main/README.md): post-generation visual hallucination correction extracts concepts, formulates questions, validates them with expert visual models, constructs visual claims and corrects text against the image. This is the closest match. Its reference stack includes GroundingDINO, model dependencies, API-key inference and GPU demo placement; not a ready offline iPhone adapter. Object/attribute benchmark improvement is not real-time door/chair safety validation. Source inspected as documentation, not executed; license/revision/model licenses and platform feasibility must be pinned before adoption.
- **Chain-of-Verification**, Dhuliawala et al., [paper](https://arxiv.org/abs/2309.11495), [ACL paper](https://aclanthology.org/2024.findings-acl.212.pdf): answering verification questions independently reduces bias from the draft before generating a revised answer. Evidence comes from text factuality tasks, not live visual navigation. Borrow independence of assessment, not a claim that another text-only pass sees the world.
- **CRITIC**, Gou et al., [paper](https://arxiv.org/abs/2305.11738), [authors' code](https://github.com/microsoft/ProphetNet/tree/master/CRITIC): tool feedback supports correction of initial outputs; evaluated QA, mathematical program synthesis and toxicity. Supports checking external evidence rather than introspection alone. Its web/code tools do not establish current physical state; its reference API setup is not authorized for private camera evidence.
- **VISCO**, Wu et al., [authors' CVPR 2025 project](https://visco-benchmark.github.io/): visual critique/correction evaluation found model critiques less helpful than human critiques and sometimes harmful. Its LookBack approach revisits the image. This is a reason to measure false corrections and missed perception errors, not merely correction count.

These works support evidence-grounded review. They do **not** validate immediate spoken physical claims followed by asynchronous repair, child comprehension of corrections, zero added latency, or safety while moving. Speak-first asynchronous correction is a product adaptation requiring separate evaluation. No quoted benchmark gains are extrapolated to this app.

## Proposed bounded contract (not new implementation)

1. Capture an immutable evidence bundle locally: original frame ID/hash, capture monotonic time plus wall time for provenance, image orientation, bounded pixel/crop reference, crop transform, sensor measurements/coverage/quality, pose and pose uncertainty, map/alignment revisions, target instance/track identity and observation interval. Keep original image to check original truth; newer image is a separate bundle. Do not store full frames just to build a permanent verifier log.
2. Bind turn/session/request ID, goal revision, source mode (live/selected/historical), answer ID, atomic claim IDs and exact span/text, speech IDs and delivered/onset state. Each claim records target, predicate, polarity, time and required evidence. Unsupported extraction or target ambiguity means unverified, not success. Decomposition must include negative assertions and relations, not only nouns.
3. Give the verifier the image/qualified sensors and neutral task (“Assess the state of this identified doorway; report open/closed/partly open/unknown with visible support”). Do not give the draft's asserted polarity during this first assessment. It may need target identity and original user question, not language-model rationale or remembered scene descriptions as ground truth. Image/OCR text is untrusted data, never instructions.
4. Only after assessment compare against atomic claim. Structured outcomes: supported, contradicted, insufficient evidence, stale, cancelled, skipped/resource unavailable. Evidence mismatch/occlusion cannot silently count as supported. Local code validates schema/owner/IDs/source capability and delivery eligibility; model confidence is not calibrated truth.
5. A text-only verifier can check whether an answer follows supplied detector facts, but cannot claim independent visual validation. Agreement between two invocations or two models is not enough for clearance, absence, ownership, identity or geometry. Prefer qualified complementary perception/sensor evidence when available; record where both agents consume the same failing observation.
6. Recheck exact target, session, goal, evidence age, map/pose, camera/private-audio/lifecycle state at result arrival, queue admission and actual speech onset. Set evidence-class freshness thresholds only after measured device evaluation; do not invent a universal safe TTL.
7. Positive result stays silent. If the original claim never started, replace/withdraw queued incorrect content without announcing a correction to unheard speech. If heard and contradicted by valid evidence, deliver one specific correction: “Correction: I said the door was open. It is closed in that image.” If current state is not established, explicitly distinguish that. Do not route through open-ended model debate.
8. Compare same-frame evidence to identify an original mistake. A later frame showing a seated person does not prove the earlier “empty chair” claim was wrong. If track/time evidence supports a change, say “The chair is occupied now”; if uncertain, say the state cannot currently be confirmed. Never retrofit later evidence onto original frame IDs.
9. If result becomes stale/cancelled, suppress its present-tense correction and invalidate dependent reuse/repeat/history as appropriate within existing ownership semantics. A correction about an already-heard historical claim may be retained locally as such, but must not revive cancelled speech or interrupt a different goal. Independently supported current hazards still use the hazard path; a stale checker result is not a new hazard observation.
10. Keep rejected/corrected claims out of future fact/memory promotion. Preserve provenance and correction linkage rather than silently rewriting user reports or transforming an LLM suggestion into sensor evidence. User-visible repeat must not repeat invalidated claims.

## Privacy, resources and delivery

- Default and required core: offline/on-device. Existing permanent rule is stronger than “cloud off by default”: private camera frames, rooms, people and memory never leave phone. Developer-cloud comparisons are only on explicitly authorized developer test data. This design grants no new opt-in or destination authority; any future policy change would require explicit authorization. A second agent must not introduce image-upload plumbing.
- Hold only bounded transient references needed for current verification, release them on cancellation/expiry under the established lifecycle, and respect image-retention/deletion controls being specified separately. No private image/prompt text in public reports or telemetry. Diagnostic aggregates should be minimal, local and nonidentifying by default.
- One bounded checker job/queue policy with deduplication and deadlines; no recursive agent delegation/retry loop. Qualify local runtime concurrency instead of assuming two model sessions execute simultaneously. Budget memory, compute, energy and thermal impact; preempt/defer ordinary checks for hazards, necessary navigation, user interruption and resource pressure.
- “Skipped” is not “verified.” Foreground fast output remains subject to existing guards even if checker is unavailable. Do not hold an urgent coded alert waiting for verifier. Correction urgency derives from actual evidence and consequence, not from a model requesting priority.
- Measure added latency and contention. Async scheduling can still slow first answer, camera processing or safety output through shared resources. Do not promise zero lag.
