## Reproduction constraints

This is a source-and-receipt checkpoint, not a turnkey portable benchmark. The CMake file uses explicit VOXBLOX_ROOT (the pinned Voxfield tree, despite the historical variable name), MINKINDR_ROOT, EIGENCHECKS_ROOT, REUSE_PREFIX and DEPS_PREFIX. Upstream sources and third-party headers/libraries are not bundled. Versions and source pins are in SOURCE_PINS.json; redistribution of those dependencies requires their own notices. The included upstream BSD licence and source-derived N1 attribution must be preserved.

The tested dependency layout is Linux x86-64 with usr/include and usr/lib/x86_64-linux-gnu below the supplied prefixes, not a generic macOS/iOS layout. The CMake header's “not configured/built in Stage A” comment describes its earlier preparation stage; the later gate did build this source. Do not interpret that historical comment as contradicting the completed build receipt. The ten upstream targets and three fixture executables are defined there; the separate ray_trace.cpp diagnostic is source evidence, not a CMake target in this file. Full guarded execution scripts and immutable freezes are not bundled, so rebuilding without recreating their resource controls is not an exact reproduction of the executed gate.

Do not run all tests without a process-tree memory watchdog: upstream_layer_utils already exceeded the retained two-GiB cap. A zero exit in the final short ray diagnostic does not make the preceding gate pass. The normal-provider ASan/UBSan pass excludes leak checking; do not silently describe it as every sanitizer passing. No resource permission for a recorded-data run is implied by publication.
